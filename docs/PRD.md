## 1. 产品定位

<a id="1-product-positioning"></a>

智能快递驿站（Smart Station）是一款**综合快递驿站存取件管理系统**，参考菜鸟驿站业务流程，支持多快递公司代收代派，覆盖包裹入库、自助查询、自助取件、自助出库的全闭环。

**核心价值主张**：
- **工作人员端**：高效入库、库存精准、滞留自动追踪、月度财务对账一键完成
- **取件用户端**：驿站现场 PAD 自助查件 → 货架自取 → 扫描机自助出库，全程无人值守
- **多端响应式**：单一前端应用同时适配 PC（≥1200px 工作人员后台）、平板 PAD（768–1200px 现场操作与取件自助）、H5（<768px 远端查件）

**竞品定位**：参考菜鸟驿站、妈妈驿站、丰巢快递柜的线下业务流程，自研轻量化系统，可独立部署于单驿站或小型连锁驿站。

## 2. 用户画像

<a id="2-user-persona"></a>

### 主要用户群体

| 角色 | 描述 | 关注点 |
|------|------|--------|
| 工作人员 | 驿站老板 / 店员 | 入库效率、库存准确率、滞留率、月度对账 |
| 取件用户 | 附近居民 / 上班族 / 学生 | 取件便捷、查询快速、流程自助、隐私保护 |
| 平台管理员 | 连锁驿站站长 | 多站点汇总（v2 预留，本期不实现） |

### 使用场景

| 场景 | 描述 | 端 |
|------|------|----|
| 日常入库 | 快递员送件到店，店员扫码入库，系统生成取件码并短信通知收件人 | PC / 平板 |
| 自助取件 | 收件人到店，PAD 输入手机号/运单号/扫码查件，获取取件码与货架位置 | Kiosk PAD |
| 自助出库 | 收件人从货架取件后，到扫描机扫包裹条码完成出库 | 扫描机 |
| 滞留追踪 | 超期件自动提醒、退回处理 | PC |
| 月度对账 | 与快递公司结算代收代派费 | PC |
| 远端查件 | 收件人在家查包裹状态（不可自助出库） | H5 |

## 4. 功能详细需求

<a id="4-feature-details"></a>

### 4.1 用户认证

**路由**：`/admin/login`、`/admin/profile`、`/admin/password`

#### 4.1.1 工作人员登录
- 账号：手机号或邮箱
- 密码：8–32 位，需含字母+数字
- 连续失败 5 次锁定该账号 15 分钟
- 登录成功后 token 存 localStorage，TTL 3 天
- 登录态持久化，下次打开自动登录

#### 4.1.2 登出
- 应用内小弹窗二次确认
- 清除本地 token，跳转登录页

#### 4.1.3 密码修改
- 旧密码 + 新密码 + 确认新密码
- 新密码不能与旧密码相同

#### 4.1.4 路由守卫
- 未登录访问 `/admin/*` 自动跳转登录页
- 已登录访问登录页自动跳转工作台

### 4.2 工作台 Dashboard

**路由**：`/admin/dashboard`

#### 4.2.1 今日概览卡片
- 今日入库件数、今日出库件数、当前在库件数、当前滞留件数、当前异常件数
- 每张卡片显示环比昨日变化（百分比 + 箭头）

#### 4.2.2 今日趋势
- 按小时入库/出库双折线图（ECharts）
- 时间范围 8:00–22:00（驿站营业时间）

#### 4.2.3 待办提醒

- 工作台展示「今日到件触达」：已私信 / 未绑定 / 私信失败 / 发送失败 + 有效绑定人数，可跳转系统管理通知记录
- 超期待提醒件数（点击跳转滞留件管理）
- 异常件未处理件数（点击跳转异常件管理）
- 寄件待处理 / 待发出件数（点击跳转寄件管理并按状态筛选）

#### 4.2.4 仓库 3D 工作区
- 工作台不内嵌全仓只读 3D 总览，仅提供「数字孪生大屏」入口，避免与全屏孪生视图重复。
- 默认相机固定在全仓总览；仅在用户查询有明确目标货架时才自动聚焦，编辑状态不自动飞行。
- 管理员可从「调整布局」进入同一 3D 工作区编辑货架、门口和功能区域并统一保存。
- 支持「数字孪生大屏」演示模式（`?view=screen`）：深色科技 HUD + 仓内 3D 孪生；场景只表达位置与状态（货架号/占用色/区域门口标签），侧栏负责统计与明细（运营 KPI、货架压力明细、小时趋势与实时动态）；按 Esc 退出。
- 前端页面统一通过 `Warehouse3D` 入口使用 3D 能力，按 `variant` 区分场景：`guide`（取件导览）、`screen`（数字孪生大屏）、`editor`（布局编辑）。
- 3D 视觉主题：`ops`（运营质感）与 `screen`（大屏科技感），统一光影、接触阴影、材质与氛围层；只读/编辑场景共享同一套门店外壳、区域模型、货架模型与模型库规格，差异仅来自主题色调与是否开启拖拽编辑。
- 门店尺寸支持按真实场景配置 `bounds.width`、`bounds.depth`、`bounds.height`（米）；3D 墙体、灯光和大屏巡航高度必须跟随真实层高渲染，旧布局无 `height` 时使用默认层高。
- 支持可选 GLB 资产热替换：将模型放入 `frontend/public/models/` 并按 manifest 命名，加载失败自动回退程序化几何。
- 只读 3D 视图支持看房式点击漫游：查询取件导览与数字孪生大屏均可点击地面，以人眼高度平滑移动到目标点；P0 版本为直线移动，不做障碍物寻路。编辑模式以拖拽建模优先，不启用点击漫游。
- 货架上的包裹模型必须严格来自真实库存数据：`inStockCount=0` 或无库存字段时不渲染货架内包裹；取件导览仅对命中包裹渲染高亮提示，禁止使用带示意编号的假包裹贴图。
- 大屏模式默认开启相机自动巡航；用户拖拽后暂停，超时恢复环绕。
- 大屏实时动态接口：`GET /api/stats/dashboard/events`，优先 `ss_parcel_events`，无数据时回退今日入/出库合成；前端 15s 轮询刷新 KPI 与动态。
- 内置占位 GLB（`frontend/public/models/*.glb`，可由 `npm run gen:models` 重生成）；替换为真实中模后自动热加载。模型库卡片必须与拖入后生成的 3D 对象规格和视觉语义一致，避免用抽象色块代替实体模型预期。

### 4.3 入库管理

**路由**：`/admin/inbound`

#### 4.3.1 扫码入库（主流程）
1. 扫运单号条码 → 自动解析快递公司
2. 自动匹配收件人信息（若快递公司接口可用）；否则手动填手机号+姓名
3. 系统自动分配货架（按货架容量与最近入库均衡）
4. 生成取件码（格式：货架号-层号-件号，如 3-2-9903）
5. 触发短信通知收件人

> **面单 OCR 快速录入**（P1，已交付）：扫码/手动录入表单顶部提供「面单识别」入口，
> 拍照或上传快递面单图片 → 后端调用腾讯云 OCR 识别 → 解析运单号/收件人姓名/手机号并回填表单，
> 工作人员核对后再确认入库。详见 4.3.8。

> **连续同收件人**（运营打磨）：扫码/手动入库成功后默认保留姓名与手机号，仅清空运单与金额，便于同一人多件连续入库；可一键「换收件人」。

#### 4.3.2 手动录入
- 字段：运单号、快递公司、收件人姓名、手机号、货架（可选自动）、备注

#### 4.3.3 批量导入
- 上传 Excel/CSV（字段同手动录入）
- 导入前预览 + 异常行高亮
- 错误行可下载修正后重传

#### 4.3.4 取件码生成规则
- 格式：`{货架号}-{层号}-{件号}`，如 `3-2-9903` = 第 3 号货架第 2 层第 9903 号
  - 货架号：1-999（1-3 位数字）
  - 层号：1-99（1-2 位数字）
  - 件号：1-9999（1-4 位数字，**随机生成**，同货架同层在库不可重复）
- 规则：件号 = 随机生成 1-9999，查同货架同层在库 `shelf_position` 集合防重，冲突重试（最多 100 次）
- 同驿站同日同货架同层不可重复
- **取件码即取件凭证，亦即包裹位置**：用户凭此码到对应货架取件，工作人员凭此码出库
- 取件码与包裹一对一

#### 4.3.5 运单号规范
- 录入与查询统一转**大写**存储与匹配（如 `sf123` → `SF123`）
- 运单号必须包含快递公司前缀（如 `SF`、`ZTO`、`YT`），用于自动识别快递公司
- 无法识别前缀时拒绝入库，提示手动选择快递公司

#### 4.3.6 货架分配规则
- 默认按货架当前容量均衡分配
- 工作人员可手动指定货架
- 货架容量超限时提示

#### 4.3.7 通知触发
- 入库成功后立即发送短信（可在系统设置中关闭）
- 短信模板：「【驿站名】您有包裹已到，取件码 3-2-9903，请凭码到对应货架取件。」

#### 4.3.8 面单 OCR 智能识别（P1，已交付）
- **入口**：扫码入库 / 手动录入表单顶部「面单识别」按钮（相机图标，触摸友好 ≥44px）
- **流程**：拍照或选图（JPG/PNG/WebP，≤5MB）→ 前端转 base64 → `POST /api/ocr/waybill` → 后端调腾讯云 `GeneralBasicOCR` 取全文 → 启发式解析 → 回填表单
- **解析字段**：
  - 运单号：取行内最长「字母+数字」编号串（排除手机号）
  - 手机号：匹配 `1[3-9]\d{9}`
  - 收件人姓名：优先「收件人/收货人/姓名」标签邻近的 2–4 位中文（排除地址用字）
- **回填策略**：仅覆盖识别到的字段，未识别项保留用户已填内容；命中情况在组件内提示需人工补全项
- **权限**：`TokenAuthGuard` + `@Roles('admin','clerk')`，与入库一致；viewer 不可用
- **边界**：仅识别回填、不落库，入库仍走 `POST /api/inbound` 人工确认；识别结果为启发式，最终以人工核对为准
- **配置**：后端 `.env` 需配 `TENCENT_SECRET_ID` / `TENCENT_SECRET_KEY` / `TENCENT_OCR_REGION`（默认 `ap-guangzhou`）；未配置时接口返回 503 友好提示，不影响手动录入
- **免费额度硬限**：腾讯云 OCR 免费额度（通用印刷体约 1000 次/月）用完后会**自动转按量付费且不报错**，故后端维护「按月全局计数 + 硬上限」。调用腾讯云**之前**先原子占用一次额度（`ss_ocr_usage` + `ss_ocr_try_consume`），到达上限直接拒绝、不再发起腾讯云请求（杜绝按量付费），前端退回手动录入。上限可用 `TENCENT_OCR_MONTHLY_LIMIT` 覆盖（默认 950，比腾讯云约 1000 次/月免费额度留 50 次安全垫）；剩余量低于 `TENCENT_OCR_WARN_THRESHOLD`（默认 50）时响应带 `quota.warning`，前端提示剩余次数。计费按腾讯云账号全局计（所有驿站共享），故计数按月份全局、不按 station。表/函数未迁移时降级为进程内内存计数，同样硬顶。

### 4.5 出库管理

**路由**：`/admin/outbound`

#### 4.5.0 与用户查询门户的关系

人工辅助出库的「查询能力」与 §4.14 用户查询门户 `/query` **对齐**（都支持手机号 / 运单号 / 取件码三种方式），但**职责不同**：

| 维度 | 用户查询门户 `/query` | 人工辅助出库 `/admin/outbound` |
|------|----------------------|------------------------------|
| 使用者 | 任意取件用户（无登录） | 驿站工作人员（登录） |
| 查询方式 | 手机号 / 运单号 / 取件码（三种） | 手机号 / 运单号 / 取件码（三种，对齐） |
| 查询接口 | `/api/kiosk/*`（公开+限流+脱敏） | `/api/outbound/search`（Token，不脱敏） |
| 结果展示 | 脱敏（手机号尾 4 位、姓名首字+**） | 完整信息（工作人员需核验） |
| 操作能力 | **仅查询展示，不可出库** | **查询 + 确认出库** |
| 输入方式 | 常驻虚拟键盘（触摸友好） | 物理键盘 / 扫码枪（工作人员操作） |
| 业务流程 | 用户查到取件码 → 口头告知工作人员 → 离开 | 工作人员查到包裹 → 核验 → 点击确认出库 |

> **典型协作场景**：用户在 `/query` 门户查到自己的取件码（如 `3-2-9903`）→ 口头告知工作人员 → 工作人员在 `/admin/outbound` 用取件码 `3-2-9903` 查询 → 核验包裹信息 → 点击「确认出库」。

#### 4.5.1 人工辅助出库（查询 + 确认两步流程）

> 1.1.0 改造：从「输入即出库」的一步流程，改为「先查列表 → 再确认出库」的两步流程，与 `/query` 门户查询能力对齐。

**第一步：查询包裹**

工作人员通过三种方式之一查询在库包裹：

| 查询方式 | 输入字段 | 校验规则 | 说明 |
|----------|----------|----------|------|
| 手机号 | 手机号（11 位） | `^1\d{10}$` | 返回该手机号名下所有在库包裹（多条） |
| 运单号 | 运单号（8–24 位，需含快递公司前缀，如 SF1234567890） | 非空，统一大写 | 返回该运单号对应的在库包裹（单条） |
| 取件码 | 取件码（格式 `X-X-X` ~ `XXX-XX-XXXXXX`） | `^\d{1,3}-\d{1,2}-\d{1,6}$` | 返回该取件码对应的在库包裹（单条） |

- 三种方式通过 Tab 切换，切换时清空输入与结果
- 调用新增接口 `POST /api/outbound/search`（Token，需 `station_id`）
- 查询结果以列表展示，**不脱敏**（显示完整收件人姓名、手机号，便于核验）
- 返回可取件包裹：`status ∈ {in_stock, overdue}`（**滞留件仍可出库**；异常/已出库/退回不返回）

**第二步：确认出库**

- 查询结果列表中，每条包裹右侧有「确认出库」按钮
- 工作人员核验包裹信息（收件人、运单号、取件码）后点击按钮
- 二次确认弹窗：「确认将运单号 XXX 的包裹标记为已出库？」
- 确认后调用 `POST /api/outbound/manual`（已有接口），状态改为 `out_stock`，记录出库时间与操作人
- 出库成功后从列表移除该条，Toast 提示「出库成功」
- 出库失败（状态已变更等）Toast 提示错误原因


#### 4.5.1.1 取件人身份核验（防冒领）
- 人工确认出库时**必须**填写收件人手机号后 4 位（向取件人当面询问）
- 后 4 位与系统不一致则拒绝出库，并提示重新确认
- 确认弹窗不展示完整后 4 位，避免店员照抄屏幕
- 可选填写核验备注（本人领取 / 代取已看证件等）
- 出库事件轨迹写入核验结果（`metadata.verify`），库存详情可回溯
- 滞留件（`overdue`）与在库件同样需核验后出库，轨迹标注「滞留件」
- 可选拍照留证：前端压缩后上传 Supabase Storage（桶 `ss-evidence`/`SUPABASE_STORAGE_BUCKET`），URL 写入出库轨迹；上传失败不阻断出库
- 可选取件签名（大件推荐）：出库核验弹窗手写板采集签名，上传同一 Storage，轨迹写入 `signatureUrl`；失败不阻断出库
- 到付运费 / 代收货款：入库可选录入金额；库存详情可改价（未出库未收款）；`collect_status=unpaid` 时人工出库须收款或免收（免收必填原因）；自助出库拦截待收款件；财务「收款日结」含免收汇总并可导出 CSV

#### 4.5.2 自助扫描出库（/scan/*）
1. 收件人在扫描机扫包裹条码（或手动输入运单号）
2. 系统校验：运单号匹配本站可取件包裹（`in_stock` 或 `overdue`）
3. 校验通过 → 标记出库，操作类型 `self_service`
4. 校验失败 → 提示原因（无此包裹 / 已出库 / 异常件）
5. 出库成功页停留 3 秒后返回扫描页

#### 4.5.3 出库记录
- 历史出库列表，可筛选时间范围、操作类型（人工/自助）、操作人

#### 4.5.4 取件码校验
- 6 位码匹配
- 同一取件码错误 3 次锁定 10 分钟
- 锁定期间不可用于人工出库
- 1.1.0：查询阶段（`/api/outbound/search`）与出库阶段（`/api/outbound/manual`）共用同一锁定计数，防止通过查询接口绕过锁定

### 4.7 滞留件管理

**路由**：`/admin/overdue`  
**权限**：admin + clerk（viewer 只读列表）  
**版本**：1.3.0（TASKS M24）

#### 4.7.1 业务目标
- 货架周转：识别超期在库件，分级提醒与退回，避免长期占架。
- 与现有数据复用：阈值来自 `ss_stations.overdue_*_days`；列表主体是 `ss_parcels`，不强制独立规则表。

#### 4.7.2 超期级别（按入库日起算，取整自然日）
| 级别 | 条件（默认阈值） | 列表色 | 系统动作 |
|------|------------------|--------|----------|
| `warn` 预警 | 天数 ≥ `overdue_warn_days`（3）且 < remind | 黄 | 标记列表；首次达到时写 `overdue_warn` 事件；包裹 `status` 可保持 `in_stock` 或置 `overdue` |
| `remind` 提醒 | 天数 ≥ `overdue_remind_days`（7）且 < return | 橙 | 写 `overdue_remind` 事件；触发免费通道通知（`overdue_remind` 模板） |
| `return` 待退回 | 天数 ≥ `overdue_return_days`（15） | 红 | 列表高亮「待退回」；引导人工退回流程 |

> 阈值可在系统设置按驿站调整（已有字段）。扫描任务将达到 warn 及以上且仍为 `in_stock` 的包裹批量更新为 `status=overdue`。

#### 4.7.3 退回子状态（`return_stage`）
存在于列表计算字段 / 事件轨迹，不新增 parcel 列亦可：
1. `none`：未进入退回
2. `pending`：达到 return 级别或人工点「标记待退回」
3. `returning`：已生成退回意图，等待快递员取走
4. `returned`：完成退回 → 包裹 `status=returned`，写 `return_complete` 事件

**人工操作**：
- `POST /api/overdue/:id/return` body `{ action: 'start' | 'complete', note? }`
  - `start`：`return_start` 事件，返回退回摘要（运单号、快递公司、取件码）
  - `complete`：状态 `returned`，清空占用（不强制清 shelf 字段，保留历史位置）

#### 4.7.4 自动扫描
- **定时**：每天 **09:00 北京时间**（服务端 cron，时区 `Asia/Shanghai`）
- **手动**：`POST /api/overdue/scan`（admin+clerk）
- **逻辑**（单驿站维度，定时任务遍历活跃驿站）：
  1. 读取驿站阈值
  2. 查询 `status IN ('in_stock','overdue')` 且有 `inbound_at` 的包裹
  3. 计算 `days = floor((now - inbound_at) / 1d)`
  4. 升级：`in_stock` → `overdue`（若 days ≥ warn）
  5. 事件防重：同 parcel 同 `event_type` 在「当前超期周期」内不重复写（以是否已有该事件为准）
  6. remind 级触发免费通道通知（失败不阻断扫描）
- **返回**：`{ scanned, markedOverdue, warned, reminded, returnCandidates }`

#### 4.7.5 API
| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/overdue` | Token | 分页列表；query：`level=warn\|remind\|return`、`page`、`pageSize`、`keyword`(手机尾号/运单/取件码) |
| POST | `/api/overdue/scan` | admin+clerk | 手动扫描当前驿站 |
| POST | `/api/overdue/:id/return` | admin+clerk | 退回 start/complete |

列表项字段：`id, trackingNumber, pickupCode, recipientName, recipientPhone, inboundAt, days, level, returnStage, status, shelf, courier`

#### 4.7.6 前端页面
- 顶部：级别 Tab（全部 / 预警 / 提醒 / 待退回）+ 关键字搜索 +「立即扫描」按钮
- 表格分色：黄/橙/红左边框或徽章
- 行操作：进入退回（start）/ 完成退回（complete）；详情可跳库存详情
- 工作台「滞留」卡片 → `/admin/overdue`；大屏待办同理
- 响应式：PC 表格式；平板卡片列表

### 4.8 异常件管理

**路由**：`/admin/exception`  
**权限**：登记/处理 admin+clerk；列表 admin+clerk+viewer 只读  
**版本**：1.3.0（TASKS M24）

#### 4.8.1 业务目标
- 对丢失、破损、错投等末端问题登记定责，保留轨迹与处理结果。
- 与库存「批量标记异常」对齐：登记成功后包裹 `status=exception`。

#### 4.8.2 数据模型 `ss_exceptions`
| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid PK | |
| station_id | uuid | 驿站隔离 |
| parcel_id | uuid | 关联包裹 |
| type | varchar | `lost` / `damaged` / `wrong_address` / `refused` / `other` |
| description | text | 描述 |
| responsible_user_id | uuid? | 责任人（员工） |
| status | varchar | `registered` → `processing` → `resolved` / `compensated` |
| resolution | varchar? | `compensate` / `return` / `destroy` / `redeliver` |
| resolution_note | text? | 处理说明 |
| attachments | jsonb | 图片 URL 数组，最多 5 |
| created_by | uuid | 登记人 |
| created_at / updated_at / resolved_at | timestamptz | |

索引：`(station_id, status)`、`(station_id, created_at desc)`、`parcel_id`

#### 4.8.3 异常类型与处理方式
- 类型：丢失、破损、地址错误、收件人拒收、其他
- 处理：赔偿、退回、销毁、重新投递
- 状态机：
  - 登记 → `registered`（同步 parcel=`exception`，事件 `exception_register`）
  - 开始处理 → `processing`
  - 结案 → `resolved` 或 `compensated`（事件 `exception_resolve`；若 resolution=`return` 可将 parcel 置 `returned`）

#### 4.8.4 API
| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/exception` | Token | 分页；query：`status`、`type`、`page`、`pageSize`、`keyword` |
| GET | `/api/exception/:id` | Token | 详情 + 关联包裹摘要 |
| POST | `/api/exception` | admin+clerk | 登记；body：parcelId, type, description, responsibleUserId?, attachments? |
| PATCH | `/api/exception/:id` | admin+clerk | 处理；body：status?, resolution?, resolutionNote? |
| POST | `/api/inventory/batch-exception` | admin+clerk | **已有**快捷批量异常；1.3.0 起可同时写入 `ss_exceptions`（type=other） |

附件：1.3.0 接受已上传 URL 列表（≤5）；完整 Storage 上传可复用后续统一上传组件。

#### 4.8.5 前端页面
- 列表：状态/类型筛选 + 关键字；展示类型、包裹运单、登记时间、状态
- 登记：选择在库/滞留包裹（可运单搜索）+ 类型 + 描述 + 可选责任人
- 处理抽屉/弹窗：选处理方式与说明，更新状态
- 工作台「异常」卡片 → `/admin/exception?status=registered,processing`
- 侧栏菜单增加「滞留件」「异常件」（admin+clerk；viewer 可见只读）

- 每次发版由开发人员更新该配置文件，追加新版本日志
- 配置文件结构：`systemInfo`（系统介绍）+ `changelog`（版本日志数组，倒序）

**访问权限**：
- 所有登录用户可见（管理员、店员、查询员均可查看）
- 纯只读展示，无编辑入口

### 4.13 通知服务

> **路线决策（开发试验）**：不接商用短信，采用**免费多通道**触达。目标平台仅 PC / PAD / H5，不做小程序。

#### 4.13.1 通知模板
| 模板 | 触发 | 内容 |
|------|------|------|
| 入库通知 | 入库成功 | 【驿站名】您有包裹已到，取件码 3-2-9903，请凭码到对应货架取件。 |
| 超期提醒 | 滞留扫描 remind 级 | 【驿站名】您的包裹已到 X 天，即将退回，请立即取件。 |
| 查件验证码 | Kiosk / 查件门户 | 【智能快递驿站】您的查件验证码为 NNNNNN，5 分钟内有效。 |
| 退回通知 | 标记退回 | 【驿站名】您的包裹已退回原快递公司，运单号 Y。（模板预留） |
| 取件成功 | 出库成功 | 【驿站名】您的包裹已取出，感谢使用。（模板预留） |

#### 4.13.2 免费通道与隐私边界（`NOTIFY_CHANNELS`）
| 通道 | 配置 | 角色 | 内容 |
|------|------|------|------|
| `console` | 默认 | 开发日志 | 完整 |
| `wecom` | `WECOM_WEBHOOK_URL` | **共享公告群**（全员可见） | **仅脱敏摘要**（手机尾号），**永不发取件码/验证码** |
| `serverchan`（环境变量） | `SERVERCHAN_SENDKEY` | 管理员个人旁路 | 完整（仅管理员微信） |
| 客户绑定（主） | `WXPUSHER_APP_TOKEN` + 表 `ss_notify_bindings`（channel=`wxpusher`） | **一对一私信** | 完整取件码（扫码关注后 UID 推送） |
| 客户绑定（备选） | 表 `ss_notify_bindings`（channel=`pushplus`） | **一对一私信** | 完整取件码（客户 PushPlus token） |
| 客户绑定（兼容） | 表 `ss_notify_bindings`（channel=`serverchan`） | **一对一私信** | 完整取件码（历史 SendKey 绑定仍有效） |

- 多通道逗号组合，如 `NOTIFY_CHANNELS=console,wecom,serverchan`
- 客户绑定 API：
  - `GET /api/kiosk/notify-guide` 公示文案与企微群二维码
  - `POST /api/kiosk/notify-bind/wxpusher/start` 手机号验证后创建关注二维码
  - `POST /api/kiosk/notify-bind/wxpusher/poll` 轮询扫码 UID（间隔 ≥12s）并完成绑定
  - `POST /api/kiosk/notify-bind/pushplus` PushPlus token 绑定
  - `POST /api/kiosk/notify-bind-status` 查询是否已绑定（不含 target）
  - `POST /api/kiosk/notify-unbind` 解绑
  - `POST /api/kiosk/notify-bind` 兼容旧 Server酱 SendKey 绑定
- 查件成功页：未绑定强引导绑定；未绑定兜底文案强调到店查/看货架，群不公示取件码
- 驿站公示配置：`ss_stations.notify_config`（企微群二维码 URL、WxPusher 绑定步骤文案），在 `/query`（含 `device=h5`）与系统管理「驿站信息」维护
- 查件验证码：不进企微群；非 production 可返回 `devCode`
- 驿站开关仍用 `ss_stations.sms_enabled`（语义为「是否发送到件通知」），系统管理可开关
- 批量入库返回 `notifySummary`（已私信/未绑定/私信失败/通知已关），导入结果页展示
- 管理端「通知记录」支持到件/滞留 **重新发送**（失败补发，或客户绑定后补推取件码）；验证码不支持重发
- 入库成功响应含 `notify` 回执（是否绑定/是否私信/店员中文摘要 `staffMessage`），入库页展示运营反馈
- 滞留扫描结果含 `customerNotified` / `customerUnbound` 便于运营评估触达

#### 4.13.3 发送记录
- 写入 `ss_sms_logs`（表名历史遗留，实际为通知日志）
- `params` 含 `channels` / `channelResults` / `freeRoute: true`
- 列表查询与失败重发为后续管理页能力（当前可走 DB / 日志）

#### 4.13.4 明确不做（当前阶段）
- 不接阿里云/腾讯云商用短信
- 不做微信小程序 / 服务号订阅消息
- `SMS_PROVIDER=real` 不再触发付费短信，回退 console 并打警告日志

### 4.14 用户自助查询门户（Public Query Portal）

**路由**：`/query`（无登录，PC / 平板 / H5 三端统一入口）

> **定位**：面向**任意取件用户**的统一查件门户。用户进入页面即可看到一个常驻的虚拟键盘面板，无需登录、无需选择设备形态，直接通过手机号、运单号、取件码三种方式之一查询名下在库包裹。
>
> **与现有端的关系**：
> - `/query` 为统一用户查件门户；通过 `?device=h5|kiosk` 控制远端 / 现场布局差异。
> - 旧 `/kiosk` 页面已合并到 `/query`，无独立路由。
> - 后端复用 Kiosk 模块（`/api/kiosk/*`）；前端仅维护 `/query` 一套页面。

#### 4.14.1 页面结构

页面自上而下分为三个常驻区域：

```
┌─────────────────────────────────────────────┐
│  顶部品牌栏（Logo + 驿站名 + 切换查询方式 Tab） │
├─────────────────────────────────────────────┤
│                                             │
│  主内容区（输入框 + 查询按钮 + 结果列表）      │
│                                             │
├─────────────────────────────────────────────┤
│  虚拟键盘面板（常驻，数字/字母可切换）          │
└─────────────────────────────────────────────┘
```

- **顶部品牌栏**：左侧 Logo + 驿站名称；右侧三档查询方式 Tab（手机号 / 运单号 / 取件码）。
- **主内容区**：根据当前 Tab 展示对应输入框与查询按钮；查询后在该区域展示结果列表（不跳转页面）。
- **虚拟键盘面板**：常驻显示，点击键盘按键输入到当前聚焦的输入框；PC 端也可使用物理键盘输入，键盘面板不隐藏。

#### 4.14.2 查询方式 Tab

三种查询方式平级切换，切换时清空当前输入与结果：

| Tab | 输入字段 | 校验规则 | 键盘模式 |
|-----|----------|----------|----------|
| 手机号 | 手机号（11 位） | `^1\d{10}$` | 数字键盘 |
| 运单号 | 运单号（8–24 位，需含快递公司前缀，如 SF1234567890） | 非空，去除首尾空格，统一大写 | 字母+数字键盘（默认字母） |
| 取件码 | 取件码（格式 `X-X-X` ~ `XXX-XX-XXXXXX`） | `^\d{1,3}-\d{1,2}-\d{1,6}$` | 数字键盘（含横杠键） |

##### 方式 A：手机号查询（直接查询，无需验证码）
1. 输入 11 位手机号 → 点击「查询包裹」
2. 调用 `/api/kiosk/query-by-phone-direct`（1.1.0 新增接口）
3. 返回该手机号名下所有在库包裹（多条），脱敏展示
4. **安全约束**：依赖 IP 限流（同 IP 每分钟 ≤10 次）防恶意遍历；查询结果脱敏（手机号仅尾号 4 位，姓名首字+**）

##### 方式 B：运单号查询
1. 输入运单号（支持字母+数字，如 SF1234567890、YT9876543210）
2. 点击「查询包裹」
3. 调用 `/api/kiosk/query-by-tracking`（已有接口）
4. 仅返回该运单号对应的在库包裹（单条）

##### 方式 C：取件码查询（新增）
1. 输入取件码（格式 `X-X-X` ~ `XXX-XX-XXXXXX`，如 `3-2-9903`）
2. 点击「查询包裹」
3. 调用新增接口 `POST /api/kiosk/query-by-code`
4. 返回该取件码对应的在库包裹（单条）
5. **安全约束**：
   - 取件码组合空间有限，存在被遍历风险，必须严格限流
   - 同 IP 每分钟最多 10 次查询
   - 同取件码连续错误 5 次锁定该码 10 分钟（防暴力遍历）
   - 查询成功不锁定，查询失败（码不存在或已出库）计入错误次数

#### 4.14.3 虚拟键盘面板规范

键盘面板为**自研组件**（`src/components/ui/Keypad.tsx`），常驻显示，支持数字与字母两种模式切换。

##### 数字键盘布局
```
[ 1 ] [ 2 ] [ 3 ]
[ 4 ] [ 5 ] [ 6 ]
[ 7 ] [ 8 ] [ 9 ]
[清空] [ 0 ] [⌫ 退格]
```

##### 字母键盘布局（QWERTY）
```
[ Q ] [ W ] [ E ] [ R ] [ T ] [ Y ] [ U ] [ I ] [ O ] [ P ]
[ A ] [ S ] [ D ] [ F ] [ G ] [ H ] [ J ] [ K ] [ L ]
[ Z ] [ X ] [ C ] [ V ] [ B ] [ N ] [ M ] [⌫ 退格]
[123 切数字]                    [清空]
```

##### 交互规范
- **按键尺寸**：最小点击区 48×48px（触摸友好），按键间距 8px
- **按键反馈**：按下时背景变 `primaryLight`，文字色变 `primary`，150ms 回弹
- **输入目标**：键盘输入写入「当前聚焦的输入框」，无聚焦时无效
- **模式切换**：运单号 Tab 默认显示字母键盘；手机号/取件码 Tab 默认显示数字键盘并锁定为数字模式（隐藏切换按钮）
- **大写锁定**：字母键盘默认大写，运单号统一转为大写提交
- **PC 端兼容**：PC 端物理键盘可同时输入，虚拟键盘不隐藏；点击输入框聚焦后虚拟键盘继续可用
- **H5 端**：禁用系统软键盘弹出（输入框 `readOnly` + 虚拟键盘驱动），避免双键盘叠加

#### 4.14.4 查询结果展示

查询成功后在主内容区展示结果列表（不跳转）：

- **有结果**：以卡片列表展示在库包裹，每条卡片包含：
  - 取件码（大号等宽字体，主色高亮，如 `3-2-9903`，即包裹所在货架-层-件号）
  - 运单号、快递公司、入库时间
  - 收件人脱敏：姓名首字 + `**`，手机号仅尾号 4 位
  - 货架指引文字：「请前往 3 号货架第 2 层取件」（由取件码解析得到）
- **无结果**：展示 `EmptyState` 组件，标题「未查询到在库包裹」，描述「可能已出库或尚未到达」，按钮「重新查询」
- **查询失败**：Toast 提示错误原因（限流、验证码错误、取件码锁定等）
- **脱敏规则**：与 Kiosk 端一致，手机号仅显示尾号 4 位，姓名首字 + `**`，不返回完整信息
- **仅显示在库包裹**：已出库、已退回、异常件不在查询结果中展示

#### 4.14.5 响应式适配

| 断点 | 布局 | 键盘面板 |
|------|------|----------|
| PC（≥1200px） | 左右双栏：左侧输入区+结果（60%），右侧键盘面板（40%，垂直居中） | 右侧固定，按键尺寸 56×56px |
| 平板（768–1200px） | 上下布局：上部输入区+结果（可滚动），下部键盘面板固定 | 底部固定，按键尺寸 52×52px |
| H5（<768px） | 单列：顶部输入框，中部结果（可滚动），底部键盘面板固定 | 底部固定，按键尺寸 48×48px，占屏高 40% |

- **移动端优先**样式编写，向上适配平板与 PC
- 键盘面板在 H5/平板端始终固定可见，不随结果列表滚动
- PC 端键盘面板可设计为「可折叠」（默认展开，用户可点击收起以查看更多结果）

#### 4.14.6 安全与限流

| 维度 | 限制 | 说明 |
|------|------|------|
| 同 IP 查询频率 | 每分钟 ≤ 10 次 | 三种查询方式合并计数 |
| 同手机号验证码 | 每小时 ≤ 5 次 | 防短信轰炸 |
| 取件码错误锁定 | 连续错误 5 次锁 10 分钟 | 防遍历，锁定该取件码 |
| 验证码有效期 | 5 分钟 | 超时需重新获取 |
| 结果脱敏 | 手机号尾 4 位、姓名首字+** | 不返回完整个人信息 |
| 无操作超时 | 90 秒无操作清空输入与结果 | 防止上一用户信息残留 |

- 所有 `/query` 页面请求走 `/api/kiosk/*` 公开接口，复用 Kiosk 模块的 `ThrottlerGuard` 限流
- 取件码查询的失败计数存储在 `ss_pickup_code_attempts` 表（与出库取件码校验复用，按 `query_scope = 'kiosk'` 区分）
- 页面离开或超时后清空所有输入框与查询结果，避免隐私泄露

#### 4.14.7 与 Kiosk / H5 端的关系

| 端 | 路由 | 定位 | 处理 |
|----|------|------|------|
| **用户查询门户** | `/query` | 三端统一入口，常驻虚拟键盘 + 空闲清空 | **主入口（默认 portal）** |
| 现场 PAD 沉浸 | `/query?device=kiosk` | 与 portal 同能力，预留现场沉浸扩展 | 可选参数 |
| 远端 H5 | `/query?device=h5` | 远端手机：顶部返回、原生键盘、无虚拟键盘、无 90s 空闲清空 | **H5 入口** |
| 旧 Kiosk | `/kiosk` | 历史现场 PAD 入口 | 已合并到 `/query`（无独立页面） |

- 业务能力统一：手机号 / 运单号 / 取件码三种查询 + 脱敏结果 + 通知绑定，全部复用 `/api/kiosk/*`
- 运营现场 Pad 首页快捷方式指向 `/query` 或 `/query?device=kiosk`
- 对外分享远端查件链接使用 `/#/query?device=h5`

#### 4.14.8 数据接口清单

| 接口 | 方法 | 认证 | 说明 |
|------|------|------|------|
| `/api/kiosk/send-code` | POST | 公开+限流 | 发送短信验证码（已有） |
| `/api/kiosk/query/by-phone` | GET | 公开+限流 | 手机号+验证码查询（已有） |
| `/api/kiosk/query/by-tracking` | GET | 公开+限流 | 运单号查询（已有） |
| `/api/kiosk/query/by-code/:code` | GET | 公开+限流 | **取件码查询（新增）** |

新增接口需在 `backend/src/kiosk/kiosk.controller.ts` 与 `kiosk.service.ts` 中实现，DTO 校验取件码格式为 `^\d{1,3}-\d{1,2}-\d{1,6}$`（货架号-层号-件号），命中后返回脱敏后的单条包裹信息。

## 6. 交互规范

<a id="6-interaction-specs"></a>

### 6.1 页面导航

| 端 | 导航方式 |
|----|----------|
| PC（≥1200px） | 左侧边栏 + 顶部用户菜单 |
| 平板 PAD（768–1200px） | 底部 TabBar（工作台/入库/库存/出库/我的） |
| 用户查询门户 `/query` | 顶部品牌栏 + 查询方式 Tab + 常驻虚拟键盘，三端响应式自适应（见 §4.14.5） |
| Kiosk PAD | 全屏沉浸式，无导航栏，单页流程，超时 60s 自动返回首页 |
| 扫描机 | 全屏摄像头预览 + 扫描框 + 顶部状态条 |
| H5（<768px） | 顶部返回栏 + 单列表单 |

### 6.2 操作反馈
- **成功**：Toast 提示，1.5 秒自动消失
- **错误**：页面内错误提示或 Toast
- **加载**：骨架屏或 Loading 遮罩
- **确认**：应用内小弹窗（删除、退回、登出等敏感操作）

### 6.3 空状态
- 所有列表页必须有空状态引导（图标 + 标题 + 描述 + 操作按钮）

### 6.4 表单交互
- 必填字段标记红色星号
- 实时表单验证
- 底部固定「取消 + 保存」按钮

### 6.5 加载状态
- 首次加载：骨架屏
- 刷新：下拉刷新指示器（仅移动端）
- 提交：按钮 loading 状态

### 6.6 响应式断点
- `sm: 768px` — H5 与平板分界
- `lg: 1200px` — 平板与 PC 分界
- 移动端优先样式，向上适配

## 8. 技术约束

<a id="8-technical-constraints"></a>

### 8.1 项目架构

```
smart-station/
├── frontend/        # React 18 + Vite + TypeScript 响应式 Web（PC/平板/H5 适配）
├── backend/         # NestJS 10 + TypeScript + Supabase JS SDK
├── scripts/         # 部署脚本
└── docs/            # 文档目录
```

**两端独立架构**，共享同一 Supabase 数据库，非 monorepo。包管理器为 npm。

### 8.2 数据库约束
- 表前缀：`ss_`
- 数据库：Supabase PostgreSQL，无 ORM、无 migration 框架
- DDL 变更必须手动在 Supabase SQL Editor 执行
- `docs/database-init.sql` 是 schema 唯一真相源

**预估核心表**（实际 schema 待 database-init.sql 阶段细化）：
- `ss_users`（工作人员）
- `ss_user_sessions`
- `ss_stations`（驿站）
- `ss_staff`（员工-驿站关系）
- `ss_roles` / `ss_permissions`
- `ss_parcels`（包裹主表）
- `ss_parcel_events`（状态轨迹）
- `ss_shifts`（交接班班次）
- `ss_shelves`（货架）
- `ss_pickup_codes`（取件码）
- `ss_overdue_rules`
- `ss_exceptions`
- `ss_shippings`（寄件单）
- `ss_address_book`
- `ss_courier_companies`
- `ss_finance_bills`
- `ss_finance_items`
- `ss_sms_templates` / `ss_sms_logs`
- `ss_pickup_appointments`（轻量预约取件）
- `ss_notify_bindings` / `ss_shifts`
- `ss_devices`

### 8.3 认证机制
- **工作人员**：自定义 Token Session（非 JWT）
  - Token：`crypto.randomBytes(32).toString('hex')` 生成 64 字符 hex
  - 存储：SHA-256 hash 存入 `ss_user_sessions` 表
  - TTL：3 天
  - 客户端 `Authorization: Bearer <token>`
- **取件用户**：无需账号，Kiosk 端通过手机号 + 验证码 / 运单号 / 扫码临时查询

### 8.4 API 约束
- 所有响应被 `ResponseInterceptor` 统一包装：`{ success, message, data }`
- 时间戳自动转北京时间 `YYYY-MM-DD HH:mm:ss.SSS`
- 前端 `request<T>()` 自动解包，直接返回 `data`
- Kiosk 接口需限流（按 IP + 手机号），防恶意遍历

### 8.5 性能约束
- 列表数据分页（默认 20/页）
- 搜索 300ms 防抖
- React Query 缓存 staleTime 5 分钟
- 扫码出库接口 P95 < 500ms
- 图片上传前压缩（≤300KB）

### 8.6 部署约束
- 平台：腾讯云 CVM + Nginx + PM2（`zlspace.site/smart-station/`），详见 `docs/deployment.md`
- 前端静态 + 后端 NestJS 同机子路径反代（`/smart-station/api/` → :3030）
- 无 CI/CD，手动执行 `scripts/deploy-cvm.sh`
